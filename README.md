# inno-medical-eqm

**نگهداری پیش‌بینانه‌ی تجهیزات پزشکی**

> وضعیت: **TRL 4** — نمونه‌ی آزمایشگاهی با اعتبارسنجی اجزا روی **داده‌ی مصنوعی** (بدون داده‌ی بیمار). برای ارزیابی بالینی یا میدانی آماده نیست. ← [مستندات TRL](docs/TRL.md)

## نیاز شناسایی‌شده
خرابی ناگهانی MRI، دیالیز، ونتیلاتور و توقف خدمات.

## محصول
پیش‌بینی خرابی و زمان‌بندی نگهداری بر اساس سوابق و داده‌ی کارکرد.

## کاربران و ذی‌نفعان
مهندسی پزشکی بیمارستان، معاونت توسعه

## قابلیت‌های هدف
- شاخص سلامت هر دستگاه
- پیش‌بینی احتمال خرابی ۳۰ روز آینده
- برنامه‌ی نگهداری و قطعات

## داده
سوابق تعمیر، ساعت کارکرد، کدهای خطا. در مراحل اولیه فقط داده‌ی مصنوعی یا بی‌نام‌شده استفاده می‌شود.

## ریسک‌ها و محدودیت‌ها
نبود داده‌ی حسگر در بسیاری از دستگاه‌ها؛ شروع از سوابق تعمیر.

## مسیر پیشنهادی
1. ✅ TRL 1 → 2: تعریف نیاز و معیار موفقیت (جدول معیارها در [docs/TRL.md](docs/TRL.md)).
2. ✅ TRL 3: نمونه‌ی آزمایشگاهی روی داده‌ی مصنوعی همراه با تست.
3. ✅ TRL 4: اعتبارسنجی اجزا در آزمایشگاه با تست‌های خودکار (CI روی هر push).
4. ⬜ TRL 5: اعتبارسنجی در محیط مرتبط با داده‌ی واقعی بی‌نام‌شده — نیازمندی‌ها در [docs/TRL.md](docs/TRL.md).

## یادداشت
این ریپو بخشی از مجموعه‌ی `inno-medical-*` برای دانشگاه‌های علوم پزشکی و وزارت بهداشت است. هیچ‌یک از خروجی‌ها جایگزین قضاوت بالینی نیست.

## راه‌اندازی سریع
```bash
pip install -r requirements.txt           # فقط numpy
export PYTHONPATH=src
python -m inno_medical_eqm generate --out data/sample # تولید داده‌ی مصنوعی (قطعی با seed)
python -m inno_medical_eqm validate                   # اجرای معیارهای TRL 4 روی ۳ seed
python -m inno_medical_eqm demo
python -m unittest discover -s tests -v
```

## آنچه پیاده‌سازی شده
مدل لجستیک (numpy) برای خرابی ۳۰ روز آینده، شاخص سلامت ۰ تا ۱۰۰، برنامه‌ی نگهداری با سقف ساعت تکنسین، پیش‌بینی خرابی به تفکیک نوع دستگاه.
